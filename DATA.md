# Data card

Two files are required and are **not** committed by default (`.gitignore`): `data/pairs.csv`, `data/eval_queries.csv`.
Copy the header rows from `data/pairs_template.csv` and `data/eval_queries_template.csv`.

## `pairs.csv` (one row per preference pair)
| column | meaning |
|---|---|
| pair_id | unique id; **must be unique** (the audit reports collisions) |
| run | generation run (`initial` / `extended`) |
| question_code, question | provenance code and question text |
| context | the retrieved text actually given to the generator (needed by the judges and the scorer) |
| source_file | document the context came from |
| chosen, rejected | grounded answer with the higher TPS / ungrounded answer |
| chosen_{sg,sr,sl}, rej_{sg,sr,sl} | TPS components (grounding, relevance, lexical) |
| chosen_tps, rej_tps, margin | stored scores; margin ≥ 0.15 |

## `eval_queries.csv`
`query_id, question, context` — the 200 staff-verified queries and the context built by the retrieval stage (ColPali → text, ≤ 1,200 characters per source). The retrieval stage is not part of this package; export its output.

## Release terms (decide before making the repository public)
- The institutional documents and the staff-verified questions may be subject to the institution's permission. Release the **pairs without `context`** if the document text cannot be shared, and say so in the paper.
- Answers were generated by Qwen2-7B-Instruct; check its licence for redistribution of outputs.
- Do not publish any personal data (names, student IDs) that appear in documents.
- Publish the `train_ids_*.csv` files so that readers can see exactly which pairs trained each adapter.
